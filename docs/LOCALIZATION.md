# Localization Contract

> How the macOS app carries more than one interface language.
>
> Created by Vetcoders (c)2026

---

## 1. Model

- **English is the source and development language.** Every piece of interface
  copy is authored in English in Swift. The English text is the lookup key.
- **Every other language is a column in a String Catalog**, never a branch in
  code. Adding a language adds translations to the catalogs and nothing else.
- **The interface language follows macOS** (system language, or the per-app
  language in System Settings › General › Language & Region). The app has no
  language switch of its own and reads no language from `settings.json`.
- The dictation language (`CsLanguage`, `WHISPER_LANGUAGE`) is an STT setting.
  It is unrelated to the interface language and must stay unrelated.

Scope of this contract: the macOS app (`macos/Codescribe`). The website, the
docs, the CLI and model prompts are separate surfaces with their own rules.

### Files

| File                                                            | Role                                                                   |
| --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `macos/Codescribe/Resources/Localization/Localizable.xcstrings` | The one table for all interface copy. Keys are extracted from Swift.   |
| `macos/Codescribe/Resources/Localization/InfoPlist.xcstrings`   | System permission prompts (`NS…UsageDescription`). Keys are hand-kept. |
| `macos/project.yml`                                             | `developmentLanguage: en`, extraction build settings, test language.   |
| `scripts/l10n-sync.sh`                                          | Folds compiler-extracted strings into `Localizable.xcstrings`.         |
| `scripts/l10n-lint.py`                                          | Static catalog checks (no build needed).                               |
| `scripts/data/cldr/plurals.json`                                | Unicode CLDR plural rules: the plural forms each language owes.        |
| `docs/LOCALIZATION_LEDGER.md`                                   | Inventory: classes of copy, where they live, open decisions.           |

One table on purpose. Splitting copy across tables forces `tableName:` onto
every call site and buys nothing at this size.

## 2. Build integration

The Xcode project is generated by XcodeGen and never committed, and every build
runs from the command line. Two consequences shape the pipeline:

1. **Catalogs are ordinary resources.** They sit under the target's source root,
   so XcodeGen adds them to the Resources phase and `xcodebuild` compiles them
   into `Contents/Resources/<lang>.lproj/` — one directory per language present
   in the catalog. No language list is maintained in `project.yml`.
2. **Nothing updates the catalog automatically.** Xcode's "sync on build" is an
   IDE feature. From the CLI the Swift compiler only emits one `.stringsdata`
   file per source (`SWIFT_EMIT_LOC_STRINGS`); `scripts/l10n-sync.sh` is what
   merges them into the catalog.

### Commands

```sh
make app                 # or any Debug build: emits .stringsdata into macos/build
make l10n-sync           # fold extracted keys into Localizable.xcstrings
make verify-l10n-sync    # fail if the catalog differs from what the build extracted
make verify-l10n-catalog # static catalog lint; part of `make check`
```

The catalog tracks the **Debug** build. Debug is a superset of Release (it also
compiles `#if DEBUG` code), so every string that ships has a row.

`l10n-sync` refuses to run when any Swift source is newer than its last compile,
because the extraction data describes the last build, not the working tree.

`build-app.sh` generates UniFFI bindings in a temporary directory, normalizes
Swift/C output there, and installs each generated file (including the modulemap)
only when its bytes differ from the current file. Identical output keeps its
source mtime, so Xcode can reuse objects and extraction data without a false
freshness refusal. New or changed output receives a new mtime and still requires
compilation before `l10n-sync` accepts it. A generator or normalization failure
publishes no staged files; the temporary directory is cleaned on exit.

After changing interface copy: build, `make l10n-sync`, commit the catalog with
the code. A key that disappears from code is dropped from the catalog when it
has no translations, and marked `stale` when it has — `verify-l10n-catalog`
fails on stale rows so a translation is never orphaned silently.

## 3. Authoring rules

The single invariant: **a string that reaches the screen, VoiceOver or a tooltip
is born localized at the place where it is written as a literal.**

### R1 — Literals passed straight to SwiftUI are already localized

`Text("Save")`, `Button("Cancel")`, `Label("History", systemImage: …)`,
`Toggle("…", isOn:)`, `Picker("…", selection:)`, `TextField("…", text:)`,
`Section("…")`, `Menu("…")`, `Window("…", id:)`, `.help("…")`, `.alert("…", …)`,
`.navigationTitle("…")`, `.accessibilityLabel("…")`, `.accessibilityHint("…")`,
`.accessibilityValue("…")` take a `LocalizedStringKey`. Leave them as they are.

Interpolation works: `Text("Remove \(name)?")` becomes the key `Remove %@?`.

### R2 — Everything else is wrapped in `String(localized:)`

A literal that is not handed directly to one of the APIs above is a plain
`String` and is shown verbatim. That covers:

- stored and computed properties (`var title: String { "Audio" }`),
- enum display names, static tables, default parameter values,
- arguments of our own components (`TrayRow(title: "Quit")`),
- messages assigned to state (`errorMessage = "…"`),
- AppKit (`window.title = "Agent"`, `panel.prompt = "…"`),
- a ternary that mixes a literal with a variable
  (`Text(isSet ? "set" : unsetLabel)` is a `String`, not a key).

Write `String(localized: "Audio")`. Types stay `String`; nothing else changes.

A view component may instead take `LocalizedStringKey` (as SwiftUI's own
controls do) when every call site passes a literal and the component only
renders the value through `Text` / `Label` / accessibility modifiers.

### R3 — Things that are not copy are marked verbatim

Extraction is type-driven, so `Text("·")` lands in the catalog as a string to
translate. Symbols, punctuation, separators, key caps (`⌘`, `Fn`), the wordmark,
file paths, URLs, environment variable names, model and vendor identifiers,
sample values, and glue such as `"\(a) · \(b)"` use `Text(verbatim:)` — or a
non-literal `String` for other APIs.

Copy that only a developer build shows — the Lab pane, the rows behind
`DeveloperSurface`, the samples in `DesignGallery` — is different: it is
ordinary English and is extracted like any other. Its keys carry
`shouldTranslate: false` in the catalog, so no translation is owed for them and
the lint does not count them. The mark belongs to keys no shipped screen uses;
remove it when one starts to.

### R4 — Plurals are one string, resolved by the catalog

Never choose a noun form in code. Write the count and the plural noun once:

```swift
String(localized: "\(count) recordings")     // key: "%lld recordings"
```

and give the key plural variations in the catalog. Each language owes the forms
Unicode CLDR lists for it: `one` / `other` for English, `one` / `few` / `many` /
`other` for Polish, six for Arabic, `other` alone for Japanese. The same applies
to a count followed by an adjective or verb (`"\(n) configured"`).

A sentence with several counts stays one key. In the catalog its text names a
substitution per count (`%#@threads@`), and each substitution carries its own
argument number and plural forms:

```text
key   Moves %lld Agent threads and %lld Agent files to Trash.
en    Moves %#@threads@ and %#@files@ to Trash.
        threads (arg 1): one "%arg Agent thread" · other "%arg Agent threads"
        files   (arg 2): one "%arg Agent file"   · other "%arg Agent files"
```

English needs variations only where the singular differs. A language whose
forms differ where English does not (`%lld configured`) adds its own variations
to the same key; nothing changes in code.

Arguments keep their number and type in every form and every language. A
translation that changes the order numbers each argument (`%2$lld plików — %1$@`
for `%@ has %lld files`); numbered and unnumbered arguments are never mixed in
one string. A plural form may spell out the count that selects it
(`One recording`) and leave nothing else out; once the count is gone, the
arguments that remain carry their numbers (`One file in %2$@`), because an
unnumbered one would be read as argument 1. A string varied as a whole has
exactly one integer argument; with more, each count gets a substitution. Inside
a substitution the count is `%arg` and any other argument carries its number.
A substitution always has plural forms; outside a plural form its count cannot
be left out. `make verify-l10n-catalog` enforces all of this.

### R5 — One sentence, one string

Do not assemble a sentence from separately localized fragments, and do not
append a localized suffix to a localized prefix. Word order differs between
languages. Use one string with placeholders:

```swift
String(localized: "Couldn't apply “\(title)”: \(reason)")
```

Styled runs inside one sentence use Markdown in the key or
`AttributedString(localized:)`, not `Text + Text`.

### R6 — Identity and display stay separate

A value that is compared, persisted, sent across FFI, used as a dictionary key,
written to the Transcript Bus, logged or matched in tests is identity and is
never localized. When the same value is also shown, give it a display property:

```swift
enum Preset: String { case fast, balanced }           // identity (rawValue)
extension Preset {
  var displayName: String {                            // display
    switch self {
    case .fast: String(localized: "Fast")
    case .balanced: String(localized: "Balanced")
    }
  }
}
```

Never show `rawValue`, never branch on displayed text, never strip a prefix off
a displayed string to get at its meaning.

### R7 — Translator comments where context is missing

Add `comment:` when the English alone is ambiguous: single words (`"set"` —
adjective or verb?), fragments, labels that share wording with another control,
and every placeholder whose content is not obvious. The comment is a
`StaticString`: it cannot interpolate, so describe placeholders in words.

```swift
Text("set", comment: "Status chip: this key has a stored value")
String(localized: "\(name) lane", comment: "The placeholder is a provider name, e.g. OpenAI")
```

Two controls that share English text but need different translations get
explicit keys:

```swift
String(localized: "providers.key.state.set", defaultValue: "set", comment: "…")
```

For such a key the English is the `defaultValue:` in code. The catalog shows it
in the English column, but the build does not compile source-language rows, so
editing that column changes nothing: change the English in Swift.

`l10n-sync` prints a notice when one key is used with different comments. That
is the list of candidates for explicit keys; whether two uses need different
words is a translation decision (ledger §5).

### R8 — Dates, numbers and case go through the system

Use `FormatStyle` / `DateFormatter` styles and `Text(value, format:)` rather
than hand-built patterns, and `.textCase(.uppercase)` rather than
`.uppercased()` on copy.

An integer interpolated into localized copy is formatted for the locale
(`5,000 recordings`). That is right for a count. A number that is an identifier
— a port, a year, a build number — is interpolated as text
(`"\(String(port))"`) so it is never grouped.

### R9 — Layout must survive longer text

Translations run 15–30 % longer than English. Prefer flexible widths; where a
fixed width or `lineLimit(1)` is structural (overlay, tray), make sure the text
truncates or scales rather than clipping.

### R10 — Search aliases are two lists

Settings search matches extra terms beyond the visible title
(`settingsSearchTerms(fixed:localized:)`). Names nobody translates — products,
protocols, file names — are a fixed list in code and match in every language.
The words people would type are one catalog row per surface
(`settings.search.section.audio`), comma-separated, owned by the translator.

## 4. What is never localized

- Logs (`Logger`, `tracing`), diagnostics, receipts, report files.
- Machine contracts: Transcript Bus events, `settings.json` keys, environment
  variables, tool names, URL schemes, bundle identifiers.
- Prompts and prompt markers sent to models (`AssistivePromptPresentation`,
  `core/config/prompts.rs`, `core/prompts/`).
- User and model content: transcripts, thread titles the user typed, messages.
- Proper names: Codescribe, Whisper, Claude Code, Codex, vendor and model names.
- CLI output (`bin/`, `app/cli/`) — a separate surface.

## 5. Text that originates in Rust

Rust composes some user-visible English (error messages, status rows, agent
status lines) and hands it across UniFFI as finished sentences. Swift can
only show that text verbatim. The current seams, the reason each cannot be
localized on the Swift side alone, and the recommended contract change are
recorded in `docs/LOCALIZATION_LEDGER.md` § "Rust ↔ Swift boundary".

The rule for new bridge surface: **Rust sends a code and arguments; Swift owns
the sentence.**

## 6. Adding a language

1. Add the language to both catalogs (open them in Xcode and press `+`, or add
   the language code under each key's `localizations`).
2. Translate. `make verify-l10n-catalog` reports untranslated keys per language
   and checks that every string reads the arguments of the English source by
   number and type (R4).
3. Build. The bundle gains `<lang>.lproj`; Sparkle's own translation for that
   language activates with it.
4. Run the app under that language without changing the system setting:
   `open -a Codescribe --args -AppleLanguages '(pl)'`.

The tooling names no language but the English source, so none of it changes
when a language is added. The plural forms a language owes are read from
`scripts/data/cldr/plurals.json`, the cardinal rules Unicode CLDR publishes for
every language. A code with a script or a region (`zh-Hans`, `pt-BR`) takes the
rules of the longest prefix CLDR knows. The catalog compiler accepts a language
with plural forms missing; the lint is what refuses it. A language code CLDR has
no rules for is refused as soon as it has plural forms, never held to `other`
alone. The file is a byte-for-byte copy of one cldr-json release (`NOTICE` names
it): to pick up a newer CLDR, replace the file and update the release in
`NOTICE` and the checksum in `scripts/tests/test_l10n_lint.py`; never edit it by
hand.

A language is declared by having translations. Do not add an empty language: a
bundle that claims a language it does not carry gives a mixed interface (system
dialogs and Sparkle switch, app copy stays English).

The lint refuses a language with no translations and only reports one that is
partly translated, so a translation can be built up in the tree. A partly
translated language must not ship: before the first release that carries a
language, add a gate that requires full coverage of every declared language
(`docs/LOCALIZATION_LEDGER.md` §5.3). That gate does not exist yet.

## 7. Tests

The test scheme pins the interface language to English, so assertions on
interface copy stay stable on any host and after more languages are added.
`LocalizationFoundationTests` proves the pipeline end to end on the built app:
the bundle declares English, the permission prompts come from their catalog,
plural variations and per-count substitutions select the right form, and an
identifier key resolves to its English text.

`scripts/tests/test_l10n_lint.py` holds the catalog lint to its word: swapped
argument types, an argument dropped or added in a plural form, mixed numbering
and a substitution without plural forms are refused; a valid reordering and the
shipped catalogs pass. Languages the app does not carry yet are held to their
own plural forms (Arabic, Japanese, French, Russian, Czech, Hebrew), a regional
code to those of its language, and an unknown code is refused. It runs in
`make verify`.

Tests that assert interface copy assert the English a person reads, including
plural forms and grouped numbers. Tests that scan Swift source for a literal
break when that literal is rewrapped; keep them pointed at the current spelling.
